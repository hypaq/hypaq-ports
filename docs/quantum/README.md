# Methodology — BAP with QAOA and FALQON

## Shared operational problem

The input is the existing two-vessel, two-berth, two-slot BAP. Service lasts one
slot. One vessel has arrival slot 0, the other slot 1. Every vessel is assigned
exactly once to an available compatible berth, no earlier than arrival. Different
vessels cannot occupy the same berth/slot. Exact enumeration establishes a
minimum total waiting time of zero. The quantum algorithms do not receive its
optimal bitstring as initialization.

The classical `build_berth_qubo` and `qubo_to_ising` implementations are reused.
Their one-hot, forbidden-assignment and collision penalties remain unchanged.
There is one qubit for every vessel/berth/slot combination: eight qubits.

## Cost convention and circuit

`E(x)=offset+sum(Q[i,j]*x_i*x_j)` with an upper-triangular Q and `x_i=(1-z_i)/2`.
Write the mapped cost as `H_C=c*I+sum(h_i Z_i)+sum(J_ij Z_i Z_j)`.
Define `s=max(1,max|h_i|,max|J_ij|)` and `H_tilde=(H_C-c*I)/s`.
The same s is used for QAOA and FALQON.

Cost gates implement `exp(-i*gamma*H_tilde)` using RZ and CNOT; mixer gates
implement `exp(-i*beta*sum X)` using RX. The constant is omitted only as a global
phase during evolution. Reports restore `full_energy=s*<H_tilde>+c`.
For this input, c=13, s=3.5, and the default classical penalty is 2.

The initial state is the uniform superposition. It includes infeasible assignments.
This version uses a transverse-X mixer, not a feasibility-preserving mixer.
All samples are decoded and checked using the original operational validator.

## QAOA

QAOA alternates p cost/mixer layers. COBYLA minimizes exact simulated expectations.
Default p=2, two restarts, at most 80 objective evaluations per restart. The first
initialization has gamma=linspace(0.1,0.3,p), beta=-0.3. Other restarts use
NumPy's seeded uniform(-pi,pi) initialization. Best evaluated parameters are kept
even if the optimizer terminates because its evaluation budget was reached.

Optimizer circuits use batch mode. The final circuit is rebuilt in live mode,
because the pinned Ket API restricts `dump()` to live execution. The report
includes that final preparation and its additional expectation query.

## FALQON

Let `H_m=sum X`. Start with beta_0=0, then apply at each layer:

1. `exp(-i*dt*H_tilde)`.
2. `exp(-i*beta_k*dt*H_m)`.
3. Set `beta_(k+1)=-<i[H_m,H_tilde]>` on the updated state.

For the diagonal Ising cost, the feedback observable is
`-2*sum(h_i/s*Y_i)-2*sum(J_ij/s*(Y_i Z_j+Z_i Y_j))`.
The implementation uses Ket observables for this feedback and exact simulator
expectations. One live state is maintained; state inspection does not collapse it.
This is not a protocol for obtaining nondestructive expectations on hardware.
Hardware execution would require repeated preparations, measurement planning and
shot budgets, which are not implemented here.

The default uses 64 layers and dt=0.05. First-order splitting and finite steps
can violate monotonic energy descent. The observed number of increases is
reported. There is no assertion of global convergence, optimality, immunity to
local minima, or guaranteed superiority to QAOA.

## Distribution and sampling

Exact-state probabilities are calculated from `ket.dump`. They are simulator
diagnostics and have finite numerical precision, not hardware-accessible values.
The report records the raw state norm. Tiny normalization drift up to 1e-4 is
corrected for probability calculations; larger drift raises an error. Restored
observable energy and energy from the normalized distribution can differ slightly
because of simulator roundoff. Both are retained.

Default final counts are generated by Ket's public seeded snapshot sampler.
This is classical sampling from the simulated state's Born probabilities. The
seed controls this sampling and QAOA initialization. It does not seed KBW's
native sampler. The optional `sampling='kbw_native'` mode calls `ket.sample`
and reports a null native sampling seed.

Full reports distinguish exact feasibility/optimality probability from empirical
feasibility/optimality frequency. If no feasible sample is obtained, best feasible
cost and its gap are null. Penalized energy is never substituted for waiting time.

## Resource and comparison boundaries

Report classical objective calls, quantum expectation queries, feedback queries,
state preparations, logical gate counts/depth, and elapsed time separately.
Logical depth is calculated from the explicit gate dependency order. It excludes
classical feedback latency, measurement costs, routing and hardware compilation.
QAOA's reported final-circuit gate count does not sum every optimization circuit.

Final 4096-shot samples do not account for training cost: optimizer/feedback
expectations are exact here. Same shots does not imply matched resources. This
single tiny instance and its default parameters do not support speedup or a
general algorithm ranking. Since the optimum is zero, use absolute objective
gaps instead of a ratio dividing by the optimum. No OR-Tools adapter is included.

## Validation

The quantum tests verify:

- MSB register ordering through actual Ket basis-state preparations.
- Ket cost-observable energies on all 256 computational basis states.
- QAOA gates against an independent NumPy full-statevector evolution.
- FALQON feedback sign and layer sequence against a NumPy commutator calculation.
- Seeded snapshot repeatability and native sampling counts.
- Consistency of run reports and explicit rejection of invalid configurations.

The original ten classical tests remain unchanged. State-vector comparisons
allow documented numerical tolerances; quantum tests do not require the
heuristics to find the optimum or declare one algorithm a winner.
